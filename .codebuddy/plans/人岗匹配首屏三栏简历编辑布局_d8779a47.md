## 产品概述

重构人岗匹配决策工作台的第一个页面（简历入口 `view-resume`），将其从当前的「简历文件卡片 + 快速指标」布局，改为参考图所示的三栏「简历编辑工作台」布局：左侧完整简历预览、中间词条导航、右侧可编辑功能区。仅改动第一个页面，后续匹配/岗位/详情等跳转页面保持不变；配色、字体、圆角、暗色基调沿用现有 match.css 设计系统（玫红 `#c84c5a` + 深底 `#06070a`）。

## 核心功能

- **左侧完整简历预览（约 1/4 宽）**：以卡片堆叠形式展示完整简历，包括头像/姓名、个人信息、教育经历、项目经历、工作经历、专业技能、自我评价等分块内容，数据来源于解析后的简历结构。
- **中间词条导航（约 1/4 宽）**：列出 6 个词条——个人信息、教育经历、项目经历、工作经历、专业技能、自我评价（「专业技能」与「自我评价」拆分为两个独立词条）。点击某词条高亮并在右侧切换对应内容。
- **右侧功能区（约 2/4 宽）**：顶部展示当前词条的「修改建议」卡片（mock 建议文本），下方为可编辑面板（词条对应简历段落），支持直接修改内容并保存到前端 state，保存后给出提示。
- **顶部操作条与底部生成按钮区**：顶部保留操作按钮（如「分析」「匹配」等）与简历简略概览；底部保留 AI 生成/停止生成按钮区，保持与原页面的交互风格一致。
- **数据与上传**：默认渲染示例简历 `张三_Java后端开发.txt`；保留上传入口，上传后解析文件并将结构化分块数据写入 `window.matchState`。暂不接入真实 AI 分析，仅前端 mock 一段修改建议文本。

## 技术栈

- 原生 HTML + CSS + 原生 JavaScript（IIFE 模块模式，无框架、无构建步骤），与现有 match.html / match.js / match.css 完全一致。
- 复用现有 CSS 设计 token（`--bg`、`--rose`、`--surface`、`--ink`、`--line` 等变量）与组件类（`.mod`、`.chip`、`.btn-sm`、`.mod-label` 等）。
- 数据持久化：写入 `window.matchState`（内存态，前端 state），不涉及后端。

## 实现方案

### 总体策略

保持现有「多视图」架构不变（`view-resume` / `view-match` / `view-jobs` 等），仅重构 `#view-resume` 内部 DOM 结构，并在 `match.js` 中新增针对简历分块的数据结构、渲染函数与编辑事件绑定。推荐**不新增独立视图**，而是在 `view-resume` 内部用「词条选中态」切换右侧编辑内容，从而避免改动 `setView()` 的 `views` 数组和导航映射，最大程度控制爆炸半径。

### 数据结构设计

在 `window.matchState` 中新增 `resumeSections`（结构化分块），每项形如：

- `id`（如 `personal` / `education` / `projects` / `experience` / `skills` / `self_eval`）
- `label`（中文词条名）
- `content`（该词条的简历原文/结构化文本，用于左栏预览与右栏可编辑区）
- `suggestion`（mock 修改建议文本，用于右侧「修改建议」卡片）

同时保留现有 `MOCK_RESULT.profile` 的 `skills` / `projects` / `education` / `experience` / `summary` 字段，作为左栏预览的来源之一，避免破坏后续页面依赖（如 `renderResume`、`renderAIPanelResume` 等仍在读取 `profile`）。

### 关键设计决策

- **左/中/右三栏布局**：在 `#view-resume` 内新增 `.resume-workbench` 容器，用 CSS Grid 实现 `1fr 1fr 2fr`（或约 `minmax(220px,.9fr) minmax(180px,.7fr) minmax(320px,1.8fr)`），配合响应式断点在小屏堆叠为单列。
- **词条切换**：维护 `window.matchState.activeSection` 字段，点击中栏词条时更新该字段并调用 `renderResumeEditor()` 重绘右侧面板，不触发全局 `setView`。
- **编辑与保存**：右侧用 `contenteditable` 或 `textarea`（推荐 `textarea` 更易受控），「保存」按钮将内容写回 `matchState.resumeSections` 对应项并 `showToast('已保存', 'teal')`；编辑期间同步预览区对应分块内容。
- **上传解析**：在现有 `loadFile()` 基础上，对 TXT 做轻量正则分块（按「【教育背景】【技能】【项目经历】【自我评价】」等标题切分），填充 `resumeSections`；PDF/DOC 因当前为前端演示态，上传后仍回退到示例结构化数据或保留原文件态，后续可接入真实解析。
- **性能**：分块渲染均为少量 DOM（6 个词条 + 若干预览卡片），无列表虚拟化需求；编辑输入用「失焦/点击保存时写回」而非每键重绘整页，避免多余 re-render。
- **向后兼容**：不修改 `setView`、`bindMatchCond`、`bindJobs`、`bindDetail` 等函数；`renderResume()` 仅重构 view-resume 内部渲染，保留 `md-start-match`、`md-view-resume`、`md-change-resume`、`md-sample-resume` 等既有按钮 ID 与行为，确保「开始匹配」等跳转链路不受影响。

### match.html 改动（第 82-149 行 #view-resume 区域）

将原有 `.resume-grid` + `.resume-quickstrip` + `.resume-focus-grid` + `.resume-summary` 替换为：

- 顶部操作条 `.resume-toolbar`（保留「开始匹配」`md-start-match` 等按钮 + 简历概览摘要）
- 三栏容器 `.resume-workbench`
- 左栏 `.resume-preview`（`id="resume-preview"`，由 JS 渲染完整简历卡片堆叠）
- 中栏 `.resume-sections-nav`（`id="resume-sections-nav"`，由 JS 渲染 6 个词条按钮）
- 右栏 `.resume-editor`（含「修改建议」卡片 `id="resume-suggestion"` + 编辑区 `id="resume-editor-text"` + 保存按钮 `id="resume-editor-save"`）
- 底部生成按钮区 `.resume-generate-bar`（保留 AI 生成/停止交互风格）

### match.js 改动

1. 在 `window.matchState` 增加 `activeSection: 'personal'`。
2. 新增 `RESUME_SECTIONS` 常量或 `buildResumeSections()` 函数，生成 6 个词条的 `{ id, label, content, suggestion }`，内容与 `张三简历.txt` 对齐。
3. `initMatch()` 中初始化 `demoState.resumeSections = buildResumeSections()`。
4. 重构 `renderResume()`：不再只渲染单张文件卡，改为调用 `renderResumePreview()` / `renderResumeNav()` / `renderResumeEditor()` 三个子函数。
5. `bindEntry()` 中新增：中栏词条点击事件（切换 `activeSection` 并重绘）、保存按钮事件（写回 content 并 toast）、以及保留原上传/示例/开始匹配事件。
6. 保留 `loadFile()` 上传解析逻辑，TXT 场景做简单分块并更新 `resumeSections`。
7. 右侧 AI 面板 `renderAIPanelResume()` 保持可用（仍可读取 `profile`），可选地显示当前选中词条的简要证据。

### match.css 改动

追加以下样式（复用 `:root` 变量，不引入新色值）：

- `.resume-toolbar`、`.resume-workbench`（三栏 grid）
- `.resume-preview`、`.resume-preview-card`（卡片堆叠，含头像占位、分块标题）
- `.resume-sections-nav`、`.resume-section-item`（含 `.is-active` 高亮，使用 `--rose-wash` + `--rose`）
- `.resume-editor`、`.resume-suggestion-card`、`.resume-editor-field`（textarea 样式）、`.resume-generate-bar`
- 响应式断点（`@media`）在窄屏将三栏堆叠为单列，沿用现有 823-838 行的断点风格。

### 需要注意的回归点

- 保持 `#view-resume` 内的既有按钮 ID（`md-start-match`、`md-view-resume`、`md-change-resume`、`md-sample-resume`、`resume-file-input`、`resume-upload-zone`）不变，否则 `bindEntry()` 绑定会失效。
- `renderResume()` 在 `initMatch()` 中被调用，且 `renderAIPanelResume()` 也被调用，重构时需保证两者都不报错。
- 不要改动 `setView()` 的 `views` 数组与 `navMap` 映射；词条切换只在 view-resume 内部完成。
- 不要触碰 `view-match` / `view-jobs` / `view-detail` / `view-learn` / `view-compare` / `view-analysis` 及其渲染函数。

## 设计风格

延续现有「深色电影风 AI 决策工作台」的视觉语言：深底 `#06070a` 背景、玫红 `#c84c5a` 强调色、低饱和玻璃质感表面、高密度小数据单元布局。新页面采用三栏工作台结构，强调「预览—选择—编辑」的清晰信息层级与操作路径。

## 布局与交互

- **顶部操作条**：左侧品牌/页面标题，中间展示简历简略概览（姓名、方向、文件状态），右侧放置「分析」「匹配」等主操作按钮，保持与现有 `.wks-topbar` 一致的高度与分隔线风格。
- **左栏简历预览**：纵向卡片堆叠，含头像圆形占位、姓名与求职方向、电话邮箱等个人信息，以及教育、项目、工作、技能、自我评价等分块卡片，卡片间用细分割线与低对比底色区分，当前选中词条对应的分块在预览中高亮描边。
- **中栏词条导航**：垂直列表，每项为可点击的窄条，选中态用玫红左侧竖条 + 玫红淡底 + 玫红文字高亮，悬停态轻微提亮，形成清晰的「当前正在编辑哪个模块」提示。
- **右栏功能区**：上方「修改建议」卡片用玫红淡底 + 玫红左侧边，展示 mock 建议文本；下方编辑区为大面积文本输入框（等宽字体，便于编辑简历段落），底部「保存修改」按钮为玫红实底，点击后提示已保存并同步左栏预览。
- **底部生成按钮区**：横向操作条，含「生成 / 停止生成」等按钮，使用现有 `.btn-sm--solid` 与 `.btn-sm--ghost` 风格，提示 AI 处理状态。

## 视觉细节

- 三栏之间用 `1px` 低对比分割线或间距区分，容器圆角统一 `10px`，卡片阴影沿用 `--shadow`。
- 所有颜色严格复用现有 CSS 变量，不新增色值，保证与其余页面风格完全一致。
- 过渡使用 `0.15s` 的柔和过渡，选中/悬停仅改变边框色与背景透明度，避免突兀动画。
